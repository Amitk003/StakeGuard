# Trust and safety guide

This page explains the safety features in StakeGuard. These are not extras.
They are the point of the app.

## 1. Evidence before opinion

Every risk label comes with the exact numbers behind it. The app shows the
implied probability, the expected value, the risk score, and the source
table rows. You can check every claim yourself.

## 2. Human approval is required

The app never finalizes anything on its own. The user must click Approve,
Edit, or Reject. Without that click, no decision is written to the log.
This is a real control, not a message that says "ask before acting".

## 3. Action log

Every decision is recorded with a timestamp: what was proposed, the risk
label, the confidence, and what the user decided. The log shows a clear
history of every interaction.

## 4. Refusal when there is not enough evidence

If the match is not in the dataset or the input is unclear, the app says it
cannot assess the bet. It never makes up an answer.

## 5. PII masking

If the user writes a personal note (mood, situation), the app hides
sensitive details like email addresses, phone numbers, and names before
storing or showing anything.

## 6. High-risk warnings

When a bet is flagged high risk (for example a big stake after an emotional
note), the app says so clearly and suggests a safer path, including a
possible cool-down suggestion. It can recommend "do not bet".

## 7. Confidence labels

Each assessment shows how confident the app is. The label depends on data
quality and how complete the input is, not on guesswork.
